## 1. 관문 ② 뼈대 — CrystalNets 는 우리 위상에 무엇을 붙이나

### 1-1. 먼저 놀라운 것: CrystalNets 는 `gme` 를 **한 번도** 안 냅니다

    CR 전체 17,202 레코드에서 Topology.AllNode == 'gme' 인 것:  **0 건**
    제올라이트형 위상은 있습니다 — sod 150 · crb 85 · gis 20 · mog 18 · zni 10 · lta 6 · rho 6 · ana 8 · mer 2

**CoRE 에서 "gme" 를 찾으면 아무것도 안 나옵니다.** 하지만 gme 골격이 없는 게 아닙니다 —
**MOFid 는 `gme` 라 하는데 CrystalNets 는 `npo` 라 합니다.** 두 도구가 같은 구조에 다른 이름을 붙입니다.
(MOFid 는 금속만 마디로 보고, CrystalNets `all_nodes` 는 링커도 마디로 보는 **파생 그물**을 냅니다.)

    MOFid 가 gme 라 한 항목 8건 →  CrystalNets AllNode:  npo 7건 · unknown 1건

### 1-2. 그 일가가 누구인가 — **우리 모체의 친척이 CoRE 안에 있습니다**

    refcode   조성                              AllNode  SingleNode Cat Dim   PLD     LCD    WaterClass  출처
    GITTUZ    Zn + 니트로Im + 벤즈Im            npo      npo        1   3    8.040  10.859   **weak**   Science 2008 (Banerjee·Yaghi) 10.1126/science.1152516
    RIRDAZ    Co + 니트로Im + 벤즈Im            npo      npo        1   3    8.278  10.883   **weak**   RSC 2014 10.1039/C3CE42075B
    YOZBUL    Zn + 디클로로Im + 니트로Im        npo      npo        1   3   10.289  12.169   **weak**   JACS 2009 10.1021/ja809459e

`GITTUZ` 는 **ZIF-68**(Zn(bIm)(nIm), gme)입니다 — 우리 모체 ZIF-69 의 바로 옆 자리(ZIF-69 는 cbIm 이 bIm 대신).
**셋 다 관문 3개를 전부 통과합니다** (npo ≠ unstable/mismatch · PLD ≥ 3.3 · weak).

### 1-3. ⚠ 그런데 확실하지는 않습니다 — 반례가 하나 있습니다

    RIRDED (FSR)  Co + **디클로로벤즈Im** + 니트로Im   MOFid gme  →  CrystalNets AllNode **unknown** · WaterClass **none** · PLD 4.933

**화학적으로 우리에게 가장 가까운 것**(벤즈이미다졸레이트에 치환기가 붙은 gme)이 **위상 미상**으로 나왔습니다.
같은 논문의 ASR 판(RIRDAZ)은 `npo` 인데 FSR 판은 `unknown` 입니다 — 용매 처리에 따라 갈립니다.
우리 v3 는 GFN-FF 로 셀 고정 이완을 거쳤고 **셀이 34 % 수축**했으므로, 결과가 `npo` 일지 `unknown` 일지는
**돌려 봐야 압니다.**

### 1-4. 그리고 **ZIF-69 자체는 CoRE 에 없습니다**

Banerjee Science 2008 의 CoRE 수록분은 다섯입니다 — GITTIN(Co,sod) · GITTOT(Co,sod) · **GITTUZ(Zn,gme→npo)** ·
GITVIP01(Zn,rho) · GITWIQ(Zn,pcu). **cbIm+nIm 조합(=ZIF-69)은 없습니다.**
`LITERATURE_NOVELTY_20260909.md` 의 "gme 연속 치환율 스캔 없음" 과 같은 방향의 **독립 확인**입니다.

### 1-5. 실제로 돌리려면

    필요    CrystalNets.jl (Julia) + `juliacall`.  **이 기기에 Julia 도 juliacall 도 없습니다.**
            ⚠ `CoREMOF` 패키지 안에 위상 계산 코드는 **없습니다** — DB 의 값은 외부에서 계산돼 실려 온 것입니다.
    비용    위상 해석은 구조당 수 초. **Zeo++ 가 아니므로 RASPA 와 충돌하지 않습니다**(§5 의 9.5 GB 문제 아님).
    걸림돌  Julia 설치 하나. 계산 자체는 싸고, 지금 돌아가는 `simulate` 를 방해하지 않습니다.

## 2. 관문 ③ 물 — **규칙을 되찾아 이미 계산했습니다**

### 2-1. 규칙이 배포본에 없습니다 → 자료에서 역산

값(`WaterClass`)은 있는데 **그 값을 붙이는 규칙이 zip 어디에도 없습니다.**
등온선 + 이름표가 **13,337 쌍** 있으므로 역산했습니다(`water_class.py`).

    저친화(superweak+weak) 8,154  ·  고친화(strong 계열) 4,534
    최적 문턱  **0.1 Pa 에서 적재량 6.899e-04 mmol/g**   (P/P0 = 2.2e-5 — 확실한 Henry 영역)
    오분류     552 / 12,688 = **4.35 %**
    환산       **K_H(물) < 6.899e-03 mmol/g/Pa 이면 weak**

이름표별 0.1 Pa 적재량 중앙값(mmol/g)이 실제로 층을 이룹니다:

    superweak 0  <  weak 2.45e-05  <  strong 6.26e-03  <  strong_high_loading 0.44  <  superstrong_high_loading 4.09
    ('none' 은 압력에 무관하게 평평하고 molecules/supercell 이 4·16·36·48 같은 정수 — **실패 표식**으로 보입니다)

**한계**: 진짜 규칙은 문턱 하나가 아닙니다(4.35 % 가 안 맞음 — 등온선 **모양**을 쓰는 듯).
`_high_loading` 접미사는 **못 되찾았습니다**(최대 적재량으로 안 갈림). 그래서 **문턱에서 3배 안이면 판정을 보류**합니다.

**독립 뒷받침 둘:**
1. CoRE 자신의 gme ZIF 들(GITTUZ·RIRDAZ·YOZBUL)이 **전부 weak** 입니다 — 이 골격 일가가 원래 소수성 쪽입니다.
2. 힘장 차이의 **방향이 우리 편**입니다. 우리는 TIP5P-Ew(+`Hw none`/`Lw none`), 그들은 TIP4P.
   TIP5P 가 수소결합을 더 세게 잡으므로 우리 K_H 는 그들 눈금 대비 **높게** 나올 것이고,
   그런데도 문턱 아래라면 **weak 판정은 안전한 쪽**입니다.

### 2-3. ★ 그런데 이게 가장 중요한 발견입니다

    선택도 1위      saIm100  150.9   (우리 계열 1군)
    K_H(CO2) 1위    saIm100  4.314e-04 (우리 계열 1군)
    물 문턱까지     saIm100  **1.7 배**  ← 우리 39조성 중 **가장 가까움**

**CO₂ 에서 이기는 바로 그 조성이 친수성 경계에 가장 가깝습니다.**
술폰산 함량이 두 축을 같이 올리는데(선택도·K_H), **물도 같이 올립니다**. 정량하면:

    saIm100 대 base    선택도 ×7.51 · K_H(CO2) ×8.09 · **물 K_H ×57.2**

**물이 7배 더 빠르게 오릅니다.** 이것이 `LCD_LOADING_CONFOUND.md`·습윤 WC 계열이 보던 것과 같은 그림이고,
"술폰산을 더 넣으면 되지 않나" 에 대한 **관문 쪽 답**입니다 — saIm100 은 CoRE 의 물 관문을 아슬아슬하게 통과합니다.

## 3. 덤 — 오프셋에 안 먹히는 "우리가 얼마나 좋은가"

CoRE 안 gme 일가는 **같은 힘장**이라 그들끼리의 비교는 온전합니다. 우리 계열 안의 **배수**도 오프셋에 안 먹힙니다.
그래서 배수를 그들에게 얹어 볼 수 있습니다(가정: 배수가 골격·힘장을 건너 옮겨간다 — **가정입니다**).

    관문 통과 모집단 n=6,604 기준 백분위

    GITTUZ = ZIF-68        선택도  15.2 (50.0 %)  →  ×7.51 = **114.4**  (**91.3 %**)
                           K_H     6.91e-04 (98.6 %) → ×8.09 = 5.59e-03 (100.0 %)
    RIRDAZ = Co-ZIF-68     선택도  51.7 (80.0 %)  →  ×7.51 = **388.0**  (**99.6 %**)
                           K_H     7.42e-05 (74.6 %) → ×8.09 = 6.00e-04 (97.8 %)

> **우리 치환 화학이 CoRE 가 실제로 담고 있는 gme ZIF 에 그대로 옮겨간다면, 선택도를 중앙값(50 %)에서
> 91 % 백분위로 올립니다.** 이것이 지금 말할 수 있는 가장 강한 문장이고, **수준이 아니라 배수**에 기대고 있습니다.

⚠ 가정 둘: (ㄱ) 배수가 ZIF-68 ↔ ZIF-69 사이에서 보존된다, (ㄴ) 배수가 힘장을 건너 보존된다.
둘 다 **검증 안 됐습니다.** 갈래 (B)("다리 놓기" — CoRE 후보 N종을 우리 프로토콜로 재계산)가 정확히 이걸 재는 일이고,
**CR CIF 2,737개가 zip 안에 있으므로 내려받기 없이 시작할 수 있습니다.** GITTUZ·RIRDAZ·YOZBUL 세 개면 충분합니다.
