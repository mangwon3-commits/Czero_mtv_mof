2026-08-14. 수분 안정성 2단계(`HYDROLYSIS.md`)의 계를 조립하다가 걸렸습니다.
**찾으러 간 것이 아니라 걸려 넘어진 것입니다.**

> **이 문서는 세 번 고쳐 썼습니다.** 원인을 두 번 잘못 짚었습니다.
>
> | 판 | 원인이라고 적은 것 | 실제 |
> |---|---|---|
> | 1 | 인접 술폰산끼리 관통. 상한 75% → 62.5% | **증상** |

>
> 틀린 중간 결론을 지우지 않고 남기는 이유는, 어느 단계에서 무엇을 잘못 봤는지가
> 다음 사람에게 필요하기 때문입니다. 특히 1판과 2판은 **둘 다 그럴듯했고 둘 다

## 1. 무엇을 봤나

수분 MD 용 LAMMPS 계를 만들다가 황 하나에 결합이 **5개** 붙는 것을 봤습니다.
술폰산의 황은 4결합(C 하나 + O 셋)이어야 합니다. 원 구조를 열어 보니

```
ZIF69_saIm100.cif
  S–S   2.642 Å      서로 다른 두 술폰산기
  O–O   0.924 Å      그 두 기의 산소
  S–H   0.952 Å      황이 이웃 고리의 수소를 뚫고 들어가 있음
```

산소 두 개가 0.924 Å 떨어져 있습니다. 어떤 화학에도 이런 O–O 는 없습니다.

## 2. 진짜 원인 — 치환기를 **엉뚱한 탄소**에 달고 있었습니다

`mtv_cif_builder.py` 는 벤조 고리의 치환 자리를 **고정 상수**로 지정합니다.

```python
CBIM_ARYL_ATTACHMENT_INDEX = 4      # site["bicyclic_ring"][4] 가 치환 자리
```

24개 자리 전부에 대해 확인해 보니

```
ring[4] 에 Cl 이 붙어 있는 자리 :  6 / 24
나머지 18개는 Cl 이 ring[5] 에 있고(1.982 Å), ring[4] 는 3.002 Å 떨어져 있음
```

**6개에서만 맞습니다.** 사이트맵의 고리 원자 순서가 자리마다 일정하지 않은데,
빌더는 그것을 상수로 가정했습니다.

그래서 18/24 자리에서 빌더는 **엉뚱한 탄소에 치환기를 달고, 원래 Cl 이 있던
쪽을 향하게** 놓았습니다. 그 방향에는 이웃 고리 탄소가 있습니다. 관측된 모든
관통이 여기서 나옵니다.

```
S–C(정상 결합)  1.769 Å        같은 황이
S–C(이웃 탄소)  0.894 Å        옆 탄소를 뚫고 들어가 있음
```

치환기 종류와 무관하게 같은 자리에서 같은 크기로 나온 이유가 이것입니다.
**치환기의 성질이 아니라 어느 원자에 다는가가 틀렸습니다.**

### 두 번째 버그 — 결합 길이가 정합 오차를 물려받았습니다

치환기 좌표를 **고리 중심 기준**으로 놓았기 때문에, Kabsch 9원자 최소제곱 적합의
오차가 그대로 결합 길이가 됐습니다. 한 구조 안에서 같은 결합이 두 배 넘게 흔들립니다.

| 치환기 | 실측 결합 길이 | 이상값 |
|---|---|---|
| −SO₃H | S–C 0.941 ~ 1.832 Å | 1.77 |
| −NO₂ | N–C 0.743 ~ 1.538 Å | 1.47 |
| −F | F–C 0.674 ~ 1.402 Å | 1.35 |
| −CH₃ | C–C 0.772 ~ 2.124 Å | 1.50 |

−CH₃ 가 가장 심해 메틸 탄소가 고리 탄소에서 0.772 Å 까지 파고들었고, **그래서
−CH₃ 만 검사에 걸렸습니다. 나머지는 걸리지 않았을 뿐 똑같이 틀려 있었습니다.**

고친 뒤: **S–C 가 24개 황 전부에서 1.769 Å** 로 균일합니다.

## 2-1. (2판의 진단 — 증상이었습니다) 모체 고리가 일그러져 있습니다

빌더는 프래그먼트의 고리 9원자를 결정구조의 고리에 Kabsch 정합시킵니다.
**그런데 치환기 방향은 정합에 참여하지 않습니다** — RDKit 이 이상적으로 임베딩한
프래그먼트가 정해 준 방향을 그대로 씁니다.

이 ZIF-69 모체는 고리가 상당히 일그러져 있습니다.

```
벤조 C–C    1.273 Å     (방향족 정상 1.39)
C–Cl        1.982 Å     (정상 1.73)
```

그래서 **이상적 프래그먼트가 가리키는 방향**과 **결정구조가 실제로 Cl 을 놓아 둔
방향**이 어긋나고, 치환기가 이웃 고리 수소 쪽으로 밀려납니다. 실측:

| 치환기 | 고리 H 까지 |
|---|---|
| −SO₃H (황) | 0.952 Å |
| −CH₃ (탄소) | 0.95 Å |
| −F | **0.561 Å** |

**치환기 종류와 무관하게 전부 나타납니다.** 원인이 치환기가 아니라 모체이기
때문입니다. −F 의 0.561 Å 은 `LINKER_DESIGN_BRIEF.md` 5-6절에 이미 기록돼 있던
값입니다 — 그때는 "−F 가 원자 하나라 회전 자유도가 없어서"로 진단했는데,
**같은 값이 −CH₃ 와 −SO₃H 에서도 나온다는 사실이 그 진단을 반증합니다.**

그리고 이것이 1절의 관통도 만들었습니다. 방향이 틀어진 채로 놓이니 인접 치환기끼리
부딪혔던 것입니다. **방향을 고치자 배타적 자리쌍이 0개가 됐습니다.**

### 부차적 원인 — 회전 최적화가 순차적이었습니다

각 치환기가 **아직 배치되지 않은 이웃을 고려하지 못한 채** 각도를 골랐습니다.
−NO₂ 는 쌍별 최적이 2.90 Å 인데 실제 구조는 1.142 Å 이었습니다. 기하학이
불가능해서가 아니라 배치 순서 때문에 도달하지 못한 것입니다.

## 3. 왜 지금까지 안 걸렸나

`audit_orphans.py` 는 네 구조 모두 "고아 0 / 충돌 0 / 분리 0" 으로 통과시킵니다.
검사기가 고장 난 게 아니라, 결함이 검사기의 예외 조항 안으로 들어가 앉았습니다.

`audit_orphans.py:57` 은 비결합 충돌을 세면서 **1,3 쌍(공통 이웃을 가진 원자쌍)을
제외**합니다. 메틸의 geminal H–H 를 충돌로 세면 순수 ZIF-8 조차 결함이 되므로
그 자체로는 옳은 처리입니다. 그런데

```
겹침이 얕으면   ->  두 원자가 그냥 가깝다             ->  충돌로 잡힌다
겹침이 깊으면   ->  둘 사이에 '결합' 이 인식된다      ->  공통 이웃이 생긴다
                ->  1,3 쌍으로 분류된다              ->  예외로 빠진다
```

**결함이 충분히 심해지면 결함 탐지기에서 스스로 사라집니다.**

> 이 구멍은 **이미 문서에 적혀 있었습니다.** `LINKER_DESIGN_BRIEF.md` 5-6절:
> "1,3-쌍 제외 로직에 원자가 개수 상한 검사를 추가하는 것이 이 감사 스크립트의
> 남은 구멍입니다." 적어 두고 막지 않은 구멍이 그대로 다시 열렸고, 이번에는
> 프로젝트의 주력 결과를 통째로 삼켰습니다.

`min_pairwise_distance` 도 못 잡습니다. `structures/*.meta.json` 에 0.9238 로
**기록되어 있는데**, 빌더 하한이 0.7 Å(구조 파손 기준)이라 통과했습니다.
0.92 Å 는 O–H 결합 길이대라 "결합 하나가 좀 짧은가 보다" 로 보입니다.

## 5. 고친 것

`mtv_cif_builder.py` 에 네 가지.

1. **`attachment_index()`** — 부착 원자를 고정 상수가 아니라 **기하로** 정합니다.
   떼어낼 치환기에 가장 가까운 고리 원자를 부착점으로 삼습니다. 고리 순서가
   어떻든 기하는 하나입니다. **이것이 핵심 수정입니다.**
2. **결합 길이를 정합 오차에서 분리** — 치환기 좌표를 고리 중심이 아니라
   **프래그먼트 자신의 부착 원자** 기준으로 잡습니다. 프래그먼트의 내부 기하가
   그대로 보존되고, Kabsch 는 방향만 제공합니다.
3. **`_aligned_substituent`** — 결정구조가 실제로 비워 준 방향(C–Cl 벡터)에 맞춰
   한 번 더 회전. 축을 결정구조에서 가져오므로 임의의 보정이 아닙니다.
4. **`optimize_substituent_rotations`** — 순차 배치를 좌표 상승법 동시 최적화로.
   목적함수는 거리가 아니라 **vdW 여유**입니다(거리로 두면 결합 자체가 최솟값을
   차지해 모든 각도가 동점이 됩니다).

충돌 회피 자리 선택(`substituent_conflict_graph` / `forcing_pairs` /
`choose_conflict_free_sites`)도 남겨 두었습니다. 1·2 를 고친 뒤로는 −SO₃H 에서
배타쌍·강제쌍이 **둘 다 0** 이라 발동하지 않지만, 다른 모체에서는 필요할 수 있고
달성 불가능한 치환율에 예외를 던지는 역할도 합니다.

부수적으로 `obabel` 을 PATH 대신 같은 환경의 bin 에서 찾도록 고쳤습니다.
