## 규약 — 네 줄

### ① 한 파일에 쓰는 사람은 하나

각 기기는 **자기 우편함만** 씁니다. 남의 파일을 고치지 않습니다.
그래서 병합 충돌이 **구조적으로 발생할 수 없습니다.**

```
21_ZIF69_MTV/COMMS/desktop.md      <- 데스크탑만 씀
21_ZIF69_MTV/COMMS/laptop.md       <- 랩탑만 씀
21_ZIF69_MTV/COMMS/laptop2.md      <- laptop2 만 씀
21_ZIF69_MTV/COMMS/junseok.md      <- Junseok 만 씀
21_ZIF69_MTV/COMMS/cloud4c.md      <- 4코어 클라우드 컨테이너만 씀
21_ZIF69_MTV/COMMS/external16.md   <- 외부 16코어만 씀
21_ZIF69_MTV/COMMS/audit.md        <- 자동 일일 감사만 씀 (사람이 쓰지 않음)
```

읽는 것은 **누구나 전부** 읽습니다.

> **세션 이름은 바뀝니다.** 08-22에 클라우드 세션 이름이
> `필수 프로그램 설치 확인` → `MANGWON-desktop` 으로 바뀌어 직접 메시지
> 발송이 한 번 실패했습니다. 이름으로 부르는 경로는 언제든 끊깁니다.
> **git 이 정식 경로이고 직접 메시지는 보조입니다.**

### ② 자기 브랜치에 푸시하고, 읽을 때는 전부 가져온다

푸시는 자기 브랜치로 합니다(지시 없이 `master`에 푸시하지 않습니다).
대신 **읽는 쪽이 모든 브랜치를 가져옵니다.**

```bash
git fetch origin '+refs/heads/*:refs/remotes/origin/*'
git branch -r                                    # 어떤 기기가 있나
git show origin/<브랜치>:21_ZIF69_MTV/COMMS/<기기>.md   # 우편함 읽기
```

**`git pull` 을 쓰지 마세요.** 계산 중에 작업 파일이 바뀝니다. `fetch` 로
가져와서 `git show` 로 읽으면 작업 트리를 건드리지 않습니다.

### ③ 새 글은 맨 위에, 시각과 함께

우편함은 **역순 누적**입니다. 지운 글은 없습니다 —
"재계산 중"과 "폐기"를 구별하지 못해 데인 적이 있습니다.

```markdown
## 2026-08-22 14:30 — 제목 한 줄

**받는 곳**: cloud4c   ← 특정 기기 앞이면 명시, 전체면 생략
**요약**: 한 줄로.

본문.
```

### ④ 답이 필요하면 그렇게 적는다

```markdown
**답 필요**: 예 / 아니오
```

답이 필요한 항목은 상대 우편함에 답이 올라올 때까지 **가정하지 말고
비워 둡니다.** 이 프로젝트에서 가장 비싼 실패는 전부 "그럴듯하게 채워진 칸"
이었습니다.

낼 수 있고, 그것은 파일 대조로 드러나지 않습니다.

그래서 새 기기의 첫 결과는 **기존 값과 같은 열역학점 하나 이상**을
포함하도록 배정하고, **수를 보기 전에** 허용 편차를 등록합니다.

  등록 (`COMMS/desktop.md` 13:55).
  > **[정정] 이 대조는 애초에 "빌드 차이"를 시험할 수 없었습니다.** 컨테이너와

  > **그리고 우리 conda 빌드는 이미 검증돼 있습니다** — 08-20 에 그 소스 빌드와
