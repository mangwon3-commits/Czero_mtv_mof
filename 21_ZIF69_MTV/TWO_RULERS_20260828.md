### ⚠️ 6-1. 여는 김에 나온 별건 — 유지율 사다리가 분모를 두 가지로 씁니다

**자 문제가 아닙니다.** 같은 표 안에서 `√2` 를 붙였다 뗐다 합니다:

```
5.25 · 6.53   분모 3.41 %p        = 배치SD **한 개**
2.65 · 3.22   분모 4.82 %p        = 배치SD × **√2**
```

**규칙은 있습니다** — 한쪽이 배치 자유도 0 이면 그쪽은 산포를 안 내므로
`√2` 를 빼야 합니다. `C(24,0) = 1` 인 **`base`** 에는 제대로 적용돼
있습니다(5.25 · 6.53).

**그런데 `saIm100` 도 `C(24,24) = 1` 로 배치 자유도가 0 입니다.**
그런데 `saIm100` 이 들어간 두 칸에는 `√2` 가 붙어 있습니다:

### 6-2. 위 6-1 은 절반만 맞았습니다 — 전수로 다시 (08-28 오후)

데스크탑이 *"보정이 한 방향뿐이면 자기 검증이 안 된다"* 고 지적해,
**값을 보기 전에 조합 자유도를 전수로 적고** 다시 했습니다.

```
base       0/24  C=**1**          saIm075   18/24  C=134,596
saIm025    6/24  C=134,596        saIm0875  21/24  C=2,024
saIm050   12/24  C=2,704,156      saIm0917  22/24  C=276
saIm0583  14/24  C=1,961,256      saIm0958  23/24  C=**24**
saIm0625  15/24  C=1,307,504      saIm100   24/24  C=**1**
saIm0667  16/24  C=735,471
```

**`C=1` 은 `base` 와 `saIm100` 둘뿐입니다.** `saIm0958` 은 24 로 0 이 아닙니다.

#### 6-2-1. `1.97` 은 `√2` 문제가 아니었습니다

분모를 열어 보니 **이웃 비교가 아니라 고원 평균과의 비교**입니다:

```
1.97 = |고원평균 75.47 − saIm0958 65.98| / (3.41·√2)
3.09 = |고원평균 75.47 − saIm100  60.56| / (3.41·√2)
```

고원은 **8조성**이라 평균의 배치 산포가 `SD/√8 = 1.206 %p` 인데 `3.41`
을 그대로 넣었습니다. **"평균 대 개별" 을 "개별 대 개별" 분모로 쓴
것**이고, `√2` 문제와는 별개입니다.

#### 6-2-2. `retention_sigma` 는 오차가 아닙니다

```
run_water.py:332    sigma = |c − c0| / sqrt(ec² + e0²)
```

**유의도입니다.** 오차막대로 읽으면 안 됩니다. 유지율의 진짜 통계오차는
전파해야 나오고, 배치의 **0.17~0.41배**(0.59~1.40 %p)라 작습니다 —
**배치만 쓰는 관행이 맞습니다.** 다만 `C=1` 조성은 배치가 0 이라
**통계가 유일한 오차**이므로 빼면 안 됩니다.

#### 6-2-3. 한 규칙으로 여섯 칸

분모 `= sqrt(배치_a² + 배치_b² + 통계_a² + 통계_b²)`, 배치는 `C=1` 이면 0.

| 문서 | 비교 | C 양쪽 | 일관 처리 | 방향 |
|---|---|---|---|---|
| 5.25 | `base`→`saIm025` | 1 / 134,596 | **4.91** | ↓ |
| 6.53 | `base`→`saIm050` | 1 / 2,704,156 | **6.26** | ↓ |
| 2.65 | `saIm0917`→`saIm100` | 276 / 1 | **3.62** | ↑ |
| 3.22 | `saIm050`→`saIm100` | 2,704,156 / 1 | **4.39** | ↑ |
| 1.97 | 고원평균→`saIm0958` | mean(8) / 24 | **2.56** | ↑ |
| 3.09 | 고원평균→`saIm100` | mean(8) / 1 | **10.35** | ↑ |

**방향이 한쪽이 아닙니다.** `base` 가 낀 둘은 내려가고(base 의 통계오차가
분모에 들어가서), `saIm100` 이 낀 셋은 올라갑니다(배치 0 이 빠져서).
6-1 에서 한 방향으로 보였던 것은 **`√2` 만 건드렸기 때문**입니다.

**여섯 칸 다 문턱 1.5 위라 판정은 하나도 안 바뀝니다.** `1.97` 이 `2.56`
이 되어 문서가 적어 둔 *"아슬합니다"* 가 없어지는데, **`√2` 가 아니라
고원 평균의 `√8` 때문**입니다.

> ⚠️ **아직 적용하지 않았습니다.** `3.09 → 10.35` 가 3.4배로 가장 큰데,
> 고원 평균의 산포를 `SD/√8` 로 두는 것이 **고원 주장 자체**(χ²=4.10,
> df=7)와 같은 가정 위에 섭니다. 순환은 아니지만 두 결론이 한 가정을
> 공유합니다. **데스크탑 판단을 받고 §2·§3 재작성 때 처리합니다.
> 그 전까지 여섯 칸 다 문서값 그대로입니다.**
>
> (참고: 고원 실측 흩어짐은 2.60 %p 로 `SD 3.41` 보다 작아,
> `2.60/√8 = 0.919` 대신 `1.206` 을 쓰는 것이 보수적인 쪽입니다.)
