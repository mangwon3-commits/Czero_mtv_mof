# 용어와 평가 절차 — 정의가 사는 곳

**설명본은 노션 Part 0-E 입니다.**
https://app.notion.com/p/3c04d27e9046819cbb1ddef416828e4c

이 파일은 `CLAUDE.md` 8절("대화에서만 존재하는 용어를 만들지 마세요")에 따라
**저장소 쪽 정본**을 둔 것입니다. 세션은 서로의 대화를 모르고 공유되는 것은
파일뿐이므로, 다른 기기의 세션이 용어를 물으면 여기를 가리키세요.

## 평가 파이프라인 (관문 순서)

    ① 구조 생성 -> ② 감사 -> ③ 이완 -> ④ 전하 -> ⑤ 흡착 GCMC
       -> ⑥ 수분 경쟁 / ⑦ 작업 용량(건조) -> ⑧ 습윤 작업 용량
       -> ⑨ 구조 안정성 관문 -> ⑩ 증거표·판정

**뒤로 갈수록 조성을 떨어뜨립니다.** ⑤ 1위가 ⑥에서 꼴찌가 되고, ⑧ 1위가
⑨에서 탈락합니다. 실제로 그렇게 됐습니다. 앞 단계 숫자 하나만 떼어
"성능"이라고 말하면 틀립니다.

## 조건 용어

| 용어 | 뜻 |
|---|---|
| RH | 상대습도 = 물 분압 / 그 온도의 포화증기압 |
| RH90 | 298 K 에서 물 분압 **2852.1 Pa** (= 2852.1 / 3169) |
| RH0/25/50 | 같은 온도에서 0 / 792 / 1585 Pa |
| TSA | 온도 스윙 재생. 298 -> **373 K**, CO2 0.15 bar 유지 |
| VSA | 진공 스윙 재생. 0.15 -> **0.05 bar**, 298 K 유지 |

**습윤 작업 용량에서 물 분압은 2852.1 Pa 로 고정합니다.** 온도만 373 K 로
올리면 포화증기압이 101325 Pa 가 되므로 **RH 가 90% -> 2.8% 로 떨어집니다.**
물 분자 수는 그대로인데 비율만 바뀌는 것이고, 그래서 승온만으로 물이 빠집니다
(v3 측정 86~90%). VSA 는 온도가 그대로라 RH 90% 가 유지되어 물이 오히려 늡니다.

## 측정량

| 용어 | 단위 | 뜻 |
|---|---|---|
| 로딩 | mol/kg | 골격 **1 kg** 이 담은 손님 **몰수** (부피당이 아니라 질량당) |
| Q_st | kJ/mol | 등량 흡착열. 목표대 30~40 |
| K_H | mol/kg/Pa | 헨리 상수. Widom 삽입으로 측정 |
| 작업 용량(WC) | mol/kg | **흡착 로딩 − 탈착 로딩** |
| 유지율 | % | 습한 조건 로딩 / 건조 로딩 |

### 로딩 감각 잡기

ZIF-69 단위셀은 600원자, 질량 7,897 g/mol. 로딩에 이 질량을 곱하면
**셀당 분자 수**가 나옵니다.

    무치환  0.589 mol/kg  ->  셀당 CO2  4.7개
    saIm050 1.239 mol/kg  ->  셀당      9.8개
    saIm100 1.543 mol/kg  ->  셀당     12.2개

단위 환산 (문헌 비교용):

    mol/kg  =  mmol/g       (숫자 같음)
    cm3(STP)/g / 22.4  =  mmol/g      예: 53.3 cm3/g = 2.38 mmol/g
    wt%  =  mol/kg x 44.01 / 10       (CO2 분자량 44.01)

**로딩은 조건과 함께 적습니다.** 우리 표의 "0.15 bar 로딩"은 **298 K·RH90 표준 조건**(옛 이름 "배가스") [설계 가정: 직접접촉 냉각기(DCC)로 25 °C 까지 식힌 배가스(사용자 제안 09-11, FLUEGAS_CONDITION_20260911.md §9). 실제 후연소 흡착 온도는 313~331 K 로 이 조건이 아니며(§2·§8), 습도 축은 RH 로 보면 어긋나지 않는다(§8). 옛 이름 "배가스 조건" 은 09-11 에 정정.]
분압 0.15 bar / 298 K / 건조입니다. 문헌의 1 bar 값과 직접 비교하면
안 됩니다 -- 분압이 거의 일곱 배입니다.

**로딩과 Q_st 는 다른 질문입니다.** 로딩은 "얼마나 많이", Q_st 는
"얼마나 세게".

로딩이 커도 그 자체로는 성능이 아닙니다. 흡착제는 붙였다 떼는 순환으로
쓰므로, 재생 단계에서 떨어지지 않고 남아 있는 분량은 **다음 사이클에도
그 자리를 차지한 채 움직이지 않습니다.** 실제로 실어 나르는 것은
드나든 분량뿐입니다.

배에 1,000톤을 실었는데 항구에서 200톤이 안 내려지면 이번 항해 성과는
800톤이고, 다음 항해는 이미 200톤이 차 있는 배로 떠나는 것과 같습니다.

우리 실측 (습윤, TSA 재생):

    조성       붙은 양   재생 후 남은 양   실제 실어나른 양   회수율
    base       0.5599        0.0907           0.4692        84%
    saIm050    0.9280        0.1600           0.7680        83%
    saIm075    1.0372        0.2038           0.8333        80%
    saIm100    0.9336        0.2454           0.6883        74%

saIm100 은 붙은 양이 saIm050 과 거의 같은데(0.9336 vs 0.9280) 재생 후
남는 양이 더 많아 실제 성과는 더 낮습니다(0.688 vs 0.768). 더 세게
붙잡은 만큼 놓아주지도 못한 것입니다.

진공 재생에서는 더 심합니다 -- saIm100 은 0.9336 중 0.4358 이 끝까지
붙어 있어 실제로는 0.4978 만 실어 나릅니다.

그래서 로딩과 Q_st 는 둘 다 중간 지표이고, 합쳐서 답을 주는 것이
**작업 용량 = 흡착 로딩 - 탈착 로딩** 입니다.

## 구조 지표와 탈락선

| 약어 | 뜻 | 탈락 |
|---|---|---|
| PLD | 통과해야 하는 가장 좁은 목 | <= 3.3 A |
| LCD | 가장 큰 공동 지름 | **이완된 모체 대비** 감소 > 20% |
| AV | 접근가능부피 | < 20 A^3 |
| 최소 원자간 거리 | 구조 파탄 검출 | < 0.7 A |

## LCD 감소는 "이완 전 대비" 가 아닙니다

`risk_screen.py` 의 정의를 실측으로 확인했습니다.

    drop = (base 의 이완 후 LCD - 이 조성의 이완 후 LCD) / base 의 이완 후 LCD

즉 **이완된 무치환 모체의 공동 대비 이 조성의 공동이 얼마나 좁은가** 입니다.
그 조성이 이완 과정에서 얼마나 줄었는지가 아닙니다.

    base     이완 전 8.89809 -> 이완 후 7.63144   LCD_drop 0.0 (자기 자신이 기준)
    saIm075  이완 후 6.08504                       (7.63144-6.08504)/7.63144 = 20.26%
    saIm050  이완 후 6.58178                       (7.63144-6.58178)/7.63144 = 13.75%

**base 자신도 이완으로 LCD 가 14.2% 줄었습니다**(8.898 -> 7.631). UFF4MOF
이완이 전 구조를 수축시키므로, 기준선도 같이 움직입니다. 그래서 민감도
시험에서 루프 예산을 바꿀 때 base 를 반드시 같이 돌려야 합니다 -- 분모가
옛 값이면 비교가 성립하지 않습니다.

## `*덜수렴` 표시 — 로그 전 줄에 붙는 그것

안정성 관문 로그의 모든 줄 끝에 `*덜수렴` 이 붙습니다. **경고가 아니라
정직성 표시**입니다 -- "이 줄의 숫자는 최종 답이 아니라 중도에 멈춰
세운 상태에서 재었다" 를 알립니다.

구조 안정성을 보려면 먼저 골격을 이완해야 합니다(원자를 힘이 균형을
이루는 자리로 옮기는 계산). 보통은 반복할수록 에너지 변화가 작아지다
멈추는데, **이 계열은 멈추지 않고 진동합니다.**

    무치환 모체    50루프에서 EDiff 5.3e-08   수렴함
    치환 구조들    6~11루프에서 1~4 로 평탄    오르내림
    saIm075       EDiff 3.8 -> 123.7          오히려 상승

2026-08-09 에 상한 없이 돌렸다가 3시간 타임아웃에 걸려 산출물이 하나도
안 나왔습니다. 그래서 OUTER_LOOP_CAP = 12 로 상한을 걸고 그 시점의
구조로 판정하되, 도달한 EDiff 를 함께 기록하고 매 줄에 표시를 답니다.

선택지가 셋이었고 왜 이걸 골랐는지:

    1. 수렴할 때까지 돌린다     -> 영원히 안 끝남, 결과 0개
    2. 상한 걸고 안 적는다      -> 숫자가 완성된 결과처럼 보임
                                   ** 실패가 결과처럼 보이는 그 유형 **
    3. 상한 걸고 매 줄에 적는다  -> 채택

읽는 사람이 바꿔야 하는 행동 셋:

- LCD 감소율을 소수점까지 인용하지 말 것 (20.26% 는 정밀값이 아님)
- 집단 안에서의 위치로 읽을 것 (20.26 vs 13.75 는 유의, 20.26 vs 20.65 는 아님)
- 이 관문은 순위를 만들지 않고 탈락만 시킴. 서열은 GCMC·작업용량·수분이 정함

**그럼 믿어도 되나 -- 재봤습니다.** 상한을 12/24/36 으로 올려
base 와 saIm075 를 다시 돌린 결과 LCD 감소는 20.26 / 20.20 / 20.32%,
EDiff 는 1.790 -> 0.516 -> 0.143. **예산 3배, EDiff 12배 개선에도 답은
±0.06%p 안**이었습니다. 덜수렴이 판정을 무효화하지 않는다는 것을
가정이 아니라 측정으로 확인한 것입니다.

## 이완 용어 — `converged: false` 는 정상입니다

`risk_screen.py` 의 `OUTER_LOOP_CAP = 12` 는 의도적입니다. UFF4MOF 이완은 이
계열에서 수렴하지 않고 진동하므로, 상한을 걸고 그 시점 구조를 쓰되 도달한
EDiff 를 기록합니다. `converged` 판정선이 EDiff < 1e-4 이고 상한에서 멈춘 값이
0.4~1.8 이므로 **전 구조가 false 로 나오는 것이 정상 동작**입니다. 로그도 전
행에 `*덜수렴` 을 찍습니다. 이 관문은 정밀한 기하 결과가 아니라 **심한
불안정성의 선별**입니다.

  세대를 넘나들며 인용하지 마세요.
- **조성 태그**: `saIm`=-SO3H, `mslm`=-SO2CH3, `nbIm`=-NO2, `brbIm`=-Br,
  `cnbIm`=-CN, `cf3Im`=-CF3, `fbIm`=-F, `mbIm`=-CH3, `base`=무치환.
  전부 벤즈이미다졸 벤조 b2 자리 치환입니다.

  > 전문, `DESIGN_STUDY_20260903.md` §7-B). `cnbIm`·`fbIm` 의 v3 빌드·GCMC 는 유효합니다 —
  > `LINKER_DESIGN_BRIEF.md` §7·§10 의 "빌더로 못 만듦" 은 v2 아릴 빌더 시대의 기록입니다.

- **숫자는 자릿수로 구별**: 세 자리는 백분율(`saIm075`=75%), **네 자리는

## σ 를 읽는 법 (조원 질문 다발 — 상세는 노션 Part 0-E 8절)

**σ 는 "같은 계산을 다시 돌리면 값이 얼마나 흔들리는가" 입니다.**
GCMC 는 난수를 쓰므로 매번 조금 다른 평균이 나오고, 그 폭이 σ 입니다.

**σ 는 "실험과 얼마나 다른가" 가 아닙니다.** 같은 모형 안에서의 재현성만
말해 줍니다. 힘장이나 구조가 틀렸으면 σ 가 아무리 작아도 답은 틀립니다 --
v1 수분 결과가 σ +-1.2% 로 작았지만 구조가 깨져 통째로 무효였습니다.

두 값을 비교할 때는 각자의 σ 를 제곱합근으로 합칩니다.

    합성 σ = sqrt(σ_A^2 + σ_B^2)      몇 σ = |A - B| / 합성 σ

우리 실제 숫자로:

    습윤 WC  saIm075 0.833+-0.022 vs saIm050 0.768+-0.018
             차이 0.065, 합성 σ 0.028  ->  2.29σ   순위 인정
    Q_st     sa50nb50 30.36+-0.35 vs saIm050 29.51+-0.19 ⟨Q_st 절대값은 RT 부호 정정 전, +4.96 — QST_RT_SIGN_20260911⟩
             차이 0.85,  합성 σ 0.398  ->  2.13σ   순위 인정

**오차막대가 조금 겹쳐도 구별될 수 있습니다** -- 위 첫 줄이 그 예입니다.
눈으로 막대를 보지 말고 식을 계산하세요.

**"몇 σ" 가 무슨 뜻인가.** 말 그대로 "두 값의 차이가 흔들림 폭의 몇
배인가" 이고, 읽는 법은 **"실제로는 차이가 없는데 우연히 이만큼
벌어졌을 확률"** 입니다. 절차는 이렇습니다.

    1. 일단 "둘은 사실 같다" 고 가정한다
    2. 그러면 관측되는 차이는 0 근처에서 흔들린다. 그 폭이 합성 σ
    3. 그런데 실제 차이가 그 폭의 2.29배로 나왔다
    4. 같다고 치면 이런 일이 일어날 확률은 약 2%. 드물다
    5. 그러므로 "같다" 는 가정을 버리고 순위를 인정한다

거꾸로 차이가 흔들림 폭 안(1σ 미만)이면, 같은 데를 쏜 것과 구별할 수
없으므로 순위를 말하지 않습니다.

확률표: 1σ 32%(의미 없음), **1.5σ 13%(우리 판정선)**, 2σ 4.6%,
3σ 0.27%, 5σ 0.00006%(입자물리 발견 기준).

1.5σ 는 통계학의 표준이 아니라 **이 프로젝트가 계산 전에 정한 사내
규칙**입니다. 우린 순위를 매길 뿐 새 발견을 선언하는 것이 아니고, 너무
느슨하면 잡음을 순위로 보고 너무 엄격하면 쓸 수 있는 차이를 버립니다.

**1.5σ 미만은 "같다" 가 아니라 "모른다" 입니다.** 보고할 때는
"구별되지 않음" 으로 적으세요.

작업 용량은 두 로딩의 **차** 라 오차가 개별 로딩보다 큽니다:
saIm050 은 ads 0.9280+-0.0174, tsa 0.1600+-0.0033 이라
WC 0.7680 +- sqrt(0.0174^2+0.0033^2) = **+-0.0177** 로 ads 보다 큽니다.

문턱 판정(LCD 20% 등)은 사전 등록된 **고정 선**이라 σ 로 움직이지
않습니다. 대신 마진을 병기합니다(saIm075 0.26%p 초과 탈락, 프로토콜
민감도 +-0.06%p).

## 판정 규율

1. 1σ 병기, 차이가 **1.5σ 미만이면 순위를 매기지 않습니다**
2. σ_wc = sqrt(σ_ads^2 + σ_des^2) — 작업 용량은 오차가 더해집니다
3. 판정 기준은 **계산 전에** 등록합니다
4. 실행 조건이 방침과 달랐다면 재시도가 아니라 **다른 시험**입니다

## 자(비교 기준) — 쉬운 말로 (2026-09-16 19:05, 사용자 지적 "자라는 말이 추상적" 에 따라)
두 숫자의 차이는 그 자체로는 뜻이 없다. 같은 계산을 다시 돌려도 숫자가 조금씩 달라지므로, 차이를 항상 **"얼마나 흔들리는가" 로 나눠서** 본다.
그 나누는 값이 **자** = 비교의 분모 = 흔들림의 크기. 규칙은 하나: **차이가 자의 1.5배 이상이면 "갈림", 아니면 "못 가름"**(1.5 는 결과 전에 고정, 결과 뒤 불변).
무엇이 흔들리느냐에 따라 자가 셋:
    단위(±)     한 구조를 한 번 계산했을 때의 통계 흔들림 — RASPA 의 ±(95 % CI, ERROR_BARS.md)      "같은 구조를 다시 돌려도 이 차이가 나오나?"
    배치 단위   같은 조성인데 치환기 자리를 다르게 놓았을 때의 흔들림 — 실현 5개 값의 표준편차(SD 형, RULER_DECISION §7)   "같은 조성을 다시 만들어도 이 차이가 나오나?"
    짝 단위     두 조성을 같은 자리 배열로 짝지어 뺀 차이의 흔들림 — 짝 차이 5개의 표준편차(TSA1_REGISTRATION §2)   "짝을 다시 뽑아도 부호가 유지되나?"
예: saIm0583e 0.825 − saIm050e 0.807 = 0.017, 배치 단위 합성 ≈ 0.11 → 0.15 → 못 가름. saIm050e − base = 0.318, ÷ 0.096 → 3.3 → 갈림.
사람에게 설명할 때는 "자" 대신 **"비교 기준(흔들림)"** 이라고 쓴다. 발표용 풀이: 노션 발표 준비 가이드 §0-1.
