# RASPA 난수 시드가 고정돼 있지 않습니다 (2026-08-28)

**발견 경로:** Junseok 이 보낸 `saIm0583` 앙상블 건조 로딩이 저장소의
`results_v3ens0583.json` 과 갈렸고(χ²=36.09, dof=5, **p<0.0001**), 구조 해시와
실행 조건이 전부 일치해 남은 설명이 실행 잡음뿐이었습니다.

## 1. 사실

**러너 어디에도 `RandomSeed` 가 없습니다.** `21_ZIF69_MTV/*.py` 전수 확인,
생성된 `simulation.input` 에도 0줄. RASPA 가 기동 시각으로 시드를 만듭니다.

**그리고 시드는 배치가 아니라 작업 단위입니다** — 같은 배치 안에서 넷을
재 보니 전부 **작업 폴더 생성 + 3초**였습니다:

```
rh15_e1   1787823853 = 08-27 18:44:13    폴더 18:44:10    +3초
rh05_e2   1787845513 = 08-28 00:45:13    폴더 00:45:10    +3초
rh10_e3   1787847722 = 08-28 01:22:02    폴더 01:21:59    +3초
rh15_e5   1787882839 = 08-28 11:07:19    폴더 11:07:16    +3초
```

> Junseok 은 *"v3ens 배치 전부 1787540797"* 로 보고했는데 **이 기기에서는
> 한 배치 안에서 다릅니다.** 이 차이가 결론의 방향을 바꿉니다(3절).

## 2. `±` 가 못 담는 것

RASPA 의 `±` 는 **한 궤적 안의 블록 평균 다섯 개**의 95% 신뢰구간입니다
(`ERROR_BARS.md`). **다른 시드로 다시 돌렸을 때의 흩어짐이 아닙니다.**

Junseok 의 표와 우리 자료 사이의 χ² 에서 크기가 나옵니다:

```
χ²/dof = 36.09/5 = 7.216      실행간 SD ≈ √7.216 × (보고된 ±) = **2.69 × ±**
```

`±` 를 진짜 σ 로 환산하면(÷2.776) **실행간 SD ≈ 7.5 × 블록 σ** 입니다.

## 3. 방향 — 작업 단위 시드라서 **부풀리는 쪽**입니다

```
시드가 배치 공통이면    실행 잡음이 실현들의 **공통 성분**  ->  차분에서 상쇄
                        -> 배치 SD 가 자리 산포를 제대로 잼
시드가 작업마다면       실행 잡음이 실현 간 **독립**       ->  배치 SD 를 부풀림
                        -> "배치 산포" 에 실행 잡음이 섞여 있음
```

**측정된 것은 후자입니다.**

## 4. 무엇이 서고 무엇이 틀렸나

**거기엔 실행 잡음이 포함되는 것이 맞습니다.** 분모가 옳은 양을 재고
있습니다. 습윤 WC·저압 물·유지율 판정 전부 영향 없습니다.

## 5. 분해 — `R` 이 측정되면 갈립니다

```
앙상블 건조 로딩   배치 SD **0.0781**   평균 1.1623   상대 6.7%
                   배치SD² = 자리² + R²
```

| 실행간 SD `R` | 자리 SD | 자리가 분산에서 |
|---|---|---|
| 0.035 (= 2.69×±) | 0.070 | **80%** |
| 0.050 | 0.060 | 59% |
| 0.078 | 0 | **0%** |

**`R` 이 0.078 을 넘지 않는 한 자리 산포는 실재합니다.** 크기만 줄어듭니다.

⚠️ **Junseok 이 재는 재실행은 구조 2개 × 1회 = dof 2 입니다.** `R` 의
95%CI 가 약 `[0.5R, 2.2R]` 로 벌어져, `R=0.035` 가 나와도 상한 0.077 이라
**위 표의 마지막 줄(자리 산포 0)을 못 배제합니다.** 결과를 "측정됐다" 가
아니라 **구간**으로 적어야 합니다. 같은 비용이면 **한 구조를 3~4회**가
두 구조를 1회씩보다 `R` 추정에 낫습니다.
