# 이 폴더의 파일 역할 — `water_results.json` 을 결과로 읽지 마세요

**한 줄**: `water_results_<기기>.json` 이 결과이고, 태그 없는
`water_results.json` 은 **이어받기 상태**입니다. 지금 4행이지만 그것은
"격자 4종 중 1종만 계산됐다" 는 뜻이 **아닙니다.**

| 파일 | 행 | 조성 | 무엇 |
|---|---|---|---|
| `water_results_desktop4.json` | 4 | `saIm0583` | ✅ 결과 |

격자 4조성 전부 계산돼 있습니다. `saIm0875` 는 **두 기기가 독립으로 재서**
RH50 에서 0.03시그마로 일치합니다.

## 왜 4행짜리 반쪽이 됐나

`run_water.py` 의 저장이 **덮어쓰기**였습니다. 조성을 한 종으로 좁힌 래퍼가
돌 때마다 이 파일이 그 조성만 남기고 좁아졌습니다. 랩탑 판(12행)과
데스크탑 판(4행)이 서로를 덮었고, 병합 시점에 남은 것이 4행입니다.

**08-25 `d0b6f50` 이 그것을 병합으로 고쳤습니다.** 이 파일의 두 판은 둘 다
그 수정 **이전**에 쓰였습니다.

**자료 손실은 없습니다** — 태그 사본이 전부 남았습니다. 08-23 `79dfa04` 가
기기 태그를 강제한 판단이 여기서 값을 했습니다.

## 왜 지금 복원하지 않는가 — 스키마가 담을 수 없습니다

이 파일의 구조는 **`(조성, RH)` 하나당 한 행**입니다
(`run_water.py:355`, `merged = {(r['name'], r['RH']): r for r in prior_rows}`).

그런데 `saIm0875` 는 **랩탑과 Junseok 이 각각 잰 두 값**이 있습니다.
태그 사본 셋을 합쳐 이 파일을 복원하려면 **둘 중 하나를 골라 다른 하나를
버려야 합니다.**

    복원한 파일   saIm0875 RH50  =  1.0582  (랩탑)      <- junseok 1.0564 는 사라짐
    또는          saIm0875 RH50  =  1.0564  (junseok)   <- 랩탑 1.0582 는 사라짐

그러면 **완전해 보이는데 독립 측정 하나를 조용히 버린 파일**이 됩니다.
지금의 "반쪽이라 이상해 보이는 파일" 보다 나쁩니다 — 이상해 보이지도 않기
때문입니다. `merge_water_batches.py` 가 교차 검증 쌍을 **"덮지 않고 분리"**
하는 것이 정확히 이것을 막으려는 설계입니다.

> **그래서 복원하지 않고 이 문서를 둡니다.** 격자 전체를 한 표로 보려면
> 복원본이 아니라 병합 도구를 쓰세요:
>
>     python merge_water_batches.py \
>         v3_water_grid/water_results_desktop4.json \
>         v3_water_grid/water_results_laptop.json \
>         v3_water_grid/water_results_junseok.json
>
> 태그 없는 `water_results.json` 은 **넘기지 마세요.** `machine_of()` 가
> 거부합니다 — 넘기면 같은 행이 두 기기 몫으로 이중 계수됩니다.

## 이 파일에 표시를 못 박는 이유

`run_water.py:291` 이 이 파일을 **맨 리스트로** 읽습니다
(`prior_rows = json.load(...)` 후 바로 순회). `{"_note": ..., "rows": [...]}`
같은 감싸기를 넣으면 **이어받기가 터집니다.** 그래서 표시를 JSON 안이
아니라 이 문서에 둡니다.
