## 5b. 자 — **판정 `±` 자 6.94, 병기 σ 자 19.94**

**[2026-09-05 23:0x, MAGI-001 종합 결정 — `MULTILIGAND §8-5` 규칙]**

블록 `±`(0.45 / 13.72)는 **RASPA 95% CI**(5블록 SEM × t(0.975,4)),
`s_rep`(0.207 / 3.612)은 **5실현 SD(1σ)** 다. 한쪽으로 맞춰서만 비교한다.

    **판정 — `±` 자**   s_rep 을 **단일 실현 95% 예측구간**으로 올림 (인자 **3.041**)
                        ±' 0.774 / 17.575   ->  **6.94 단위**
    병기 — σ 자         블록 ± 를 2.776 으로 내려 1σ 로
                        ±' 0.263 / 6.122   ->  **19.94 단위**

**둘 다 문턱 1.5 를 크게 넘는다. 판정은 어느 자로도 안 바뀐다.**
**한쪽만 인용하지 않는다**(`MULTILIGAND §8-5`).

**⚠ 인자가 3.041 인 이유 — `§8-5-1` 의 2.776 과 다르다. 옮겨 쓰지 말 것.**

    3.041 = t(0.975,4) × √(1 + 1/5)   **단일 실현**의 95% 예측구간
                                       <- 이 문서: "한 실현이 평균에서 얼마나 벗어나는가"
    2.776 = t(0.975,4)                 **평균**의 95% CI
                                       <- §8-5-1: 구성이 `s_batch/√n`(평균의 SEM)

**묻는 것이 다르므로 인자가 다르다.** 두 문서 사이에서 수를 옮기면 3.3% 틀린다.

**⚠ 자를 섞은 값(±' 0.495 / 14.187 -> 8.61)은 인용하지 않는다.**
앞선 판에 그 수가 있었고, 정의 있는 두 자 어느 쪽도 아니다.

## 6. 구현 두 개가 어긋나 정의를 잡았다

`analyze_srep.py`(8.6)와 `make_srep_verdict.py`(10.9)가 다른 답을 냈다. 원인은
`±` 를 무엇으로 잡느냐였다:

    등재 ±        base 0.450 · saIm100 13.720   <- 배정문 §1 이 **명시**
    내 실측 블록 ±  base 0.405 · saIm100 10.604   (등재의 0.90배 / **0.77배**)

배정문 §1 이 `±` 를 *"한 실행의 블록 다섯"* 으로 정의하고 **그 수를 적어 두었으므로
등록대로는 등재값**이다. **내 실측을 쓰면 단위가 8.6 → 10.9 로 유리하게 커진다** —
유리한 쪽이라 더더욱 등록대로 갔다. 생성기를 고쳤고 두 구현이 이제 일치한다.

> **두 구현이 어긋난 것이 정의의 모호함을 잡았다.** 하나만 짰으면 10.9 를 냈을 수도
> 있고, 그것이 유리한 쪽이라 의심할 계기가 없었을 것이다.
