# 사슬 대 단일 — **같은 기기·같은 조성**에서 물 표류를 가른다 (등록, 랩탑 2026-09-07)

**왜**: `WATER_FIX §8` 이 *"물이 아직 오른다"* 를 일괄 딱지로 걸었는데, 자료가 갈립니다.

    laptop2 조각 사슬     5/5 상승 (블록 600 사이클)
    데스크탑 단일 3건     base **−8.2 %** · saIm050 **+22.8 %** · nbIm025 +4.1 % (Δ40)
    **랩탑 단일 8건**     평균 **+1.66 %/블록**, SE 2.14, **t = 0.78** — 0 과 구별 안 됨
                          95 % 구간 **[−3.40, +6.72]** -> laptop2 의 **+9.4~10 을 배제**

**두 갈래**: **(가) 프로토콜 특유**(사슬에서만 오름) 또는 **(나) 조성 의존**.
지금 자료로는 `base` 가 **사슬 +20.4 대 단일 −8.2** 로 갈리는데, 같은 조성·같은 힘장입니다.
**교란은 기기와 프로토콜이 섞여 있다는 것**입니다. 그래서 **같은 기기에서** 둘을 돌립니다.

## 등록 — 결과를 보기 전에

    실행    `base` · `saIm050` 를 **이 랩탑에서** `run_water_chunked.py`(v3w 설정)로 1회씩.
            `CHUNK_RUNS_ROOT=water_runs_v3w_chunk`, 결과 `v3w_water_chunk/`
            총 사이클·힘장·물 정의·압력 전부 불변(§1). 바뀌는 것은 **실행 구조** 하나
    통계    **Δ40** = (뒤 40 % 블록 평균) / (앞 40 % 블록 평균) − 1, 물 로딩.
            사슬은 25블록(600), 단일은 5블록(3,000) — **블록 길이가 다르므로
            `%/블록` 으로 비교하지 않습니다.** Δ40 은 길이에 무관한 비입니다
    비교    같은 기기·같은 조성에서 **사슬 Δ40 대 단일 Δ40**

    **예측 (가)** 프로토콜 특유 -> 랩탑 사슬 `base` Δ40 이 **다시 +20 근처**.
                 즉 사슬이면 기기와 무관하게 오릅니다
    **예측 (나)** 조성 의존 -> 랩탑 사슬 `base` Δ40 이 **단일과 같은 잡음 대역**
                 (랩탑 단일 8건의 Δ40 분포 안). 즉 오르는 것은 `base` 가 아니라 프로토콜도 아님

    갈리지 않으면  **유보.** 둘 다 적고 어느 쪽도 주장하지 않습니다

⚠️ **`base` 는 물이 셀당 약 11분자뿐이라 Δ40 잡음이 큽니다**(종합자 지적). 그래서
`saIm050`(물이 많음)을 함께 돌려 **잡음 대역 자체를 이 기기에서** 잽니다.

## 곁들여 — 씨앗 반복 (`s_rep`, v3w 계열)

    실행    `saIm025` · `saIm050` · `saIm0583` 를 **같은 프로토콜·다른 씨앗**으로 1회씩.
            `V3W_SUFFIX=_rep` -> `water_runs_v3w_rep/` · `v3w_water_rep/`
            씨앗은 RASPA 가 착수 시각으로 정하므로 **초를 어긋내 띄웁니다**
            (`SEED_TWO_MEANINGS`: 같은 초 = 같은 씨앗 = 재생)
    왜      **지금 유지율 오차에 실행 간 항이 없습니다** — 블록 ± 와 분모 ± 뿐입니다.
            이 저장소는 배치·씨앗 산포가 통계오차보다 큰 경우를 여러 번 봤습니다
    쓰는 법 `RULER_DECISION §7`: 씨앗 반복은 **통계 비교**이므로 자는 **단위(±)**.
            "배치 단위" 라고 부르지 않습니다
    **새 시험이 아닙니다** — 같은 조성·같은 설정의 반복이고, 문턱을 새로 걸지 않습니다
