## 1. 왜 이것을 재는가 — 계열 간 비교에 통제되지 않은 변수가 있습니다

`mtv_cif_builder.py:819-825` 가 **치환기 2종 이상이면 다른 경로**를 탑니다.

```python
if conflict_aware and len(subs) == 1:      # 충돌 회피 배치
    ...
else:
    if conflict_aware and len(subs) > 1:
        print("[주의] 치환기가 2종 이상이라 충돌 회피 배치를 건너뜁니다 — 무작위 배치입니다.")
    assignment = rng.choice(names, size=len(sites), p=probs)   # 무작위
```

그 결과 저장소의 구조가 **두 계열로 갈립니다**:

| 계열 | 예 | `conflict_aware` | `n_substituted` |
|---|---|---|---|
| 이원 (치환기 1종) | saIm0583 · saIm050 · saIm0917 | **True** | 기록됨 |
| 다원 (2종 이상) | sa50nb50 · sa25nb75 · ms50nb50 | **False** | `None` |

`build_v4mix.py` 는 시드를 8개까지 돌려 **조성이 우연히 맞는 것**을 골랐습니다.
조성은 맞췄지만 **배치 규약은 여전히 무작위**입니다.

**문제**: v4 의 헤드라인이 "치환 종류를 바꾸면 물 축이 움직인다"(유지율
75.19 → 84.77 → 91.91)인데, 그 비교 상대인 saIm 계열은 다른 알고리즘으로
배치됐습니다. 그리고 08-25 에 **배치가 성질을 크게 흔든다**는 것이
측정됐습니다(건조 로딩 배치 SD 0.0963, 통계 오차의 5배).

즉 v4 대 saIm 의 차이 중 **얼마가 화학이고 얼마가 배치 규약인지 분리되지
않습니다.** 앙상블로는 안 풀립니다 — 정밀해질 뿐 서로 다른 두 분포를
재는 것은 그대로입니다.

## 2. 대조군 설계 — 배치 규약만 바꿉니다

`conflict_aware` 는 빌더의 **함수 인자**입니다. 이원 조성에 `False` 를 주면
같은 조성을 무작위 배치로 만들 수 있습니다.

    기존(측정 완료)  saIm0583  충돌 회피  시드 0,1,2,3,4,5   n=6
    대조군(신규)     saIm0583  **무작위**  시드 5개           n=5
                     태그 saIm0583r1 ~ r5   (r = random placement)

**조성·원소·셀·이완·전하·GCMC 규약이 전부 동일하고 배치 알고리즘만
다릅니다.** 비교 대상이 이미 측정돼 있어 **건조 로딩만으로 판정**됩니다 —
물까지 갈 필요가 없습니다.

무작위 경로는 조성을 다항 추출로 뽑으므로 정확히 14/24 가 안 나옵니다.
**시드를 돌려 S 원자 수가 정확히 14 인 것만 채택**합니다. 이것은 편향이
아닙니다 — 우리가 원하는 것이 "같은 조성, 다른 배치" 이므로 조성으로
조건부화하는 것이 정확히 맞는 표집입니다.

## 3. 판정 — 수를 보기 전에 고정

    M_ca, s_ca = 충돌 회피 6실현의 건조 0.15 bar 로딩 평균·표본SD
    M_r,  s_r  = 무작위 5실현의 같은 값
    (평균·SD 는 전부 그 집합 전체로 냅니다. **leave-one-out 금지.**)

두 문턱을 **서로 다른 질문**에 겁니다.

**(가) 검출 가능한가** — 평균 이동이 통계적으로 잡히는가

    SE = sqrt(s_ca^2/6 + s_r^2/5)
    |M_ca - M_r| / SE  >= 1.5  ->  이동 검출됨

**(나) 유의미하게 큰가** — 이미 감수하는 배치 산포에 비해 큰가

    s_comb = sqrt(s_ca^2 + s_r^2)
    |M_ca - M_r| / s_comb  >= 1.5  ->  이동이 유의미함

### 결론 매핑

| (가) | (나) | 판정 | 다음 |
|---|---|---|---|
| 아니오 | 아니오 | **null** — 배치 규약이 성질을 안 움직인다 | 교란 해소. v4·삼원 비교를 이 측정 위에 놓는다. 빌더 확장은 "있으면 좋은 것" 으로 내림 |
| 예 | 아니오 | **작은 오프셋** | 크기를 명시해 병기하고 진행. 빌더 확장 보류 |
| 예 | 예 | **non-null** | **빌더 확장(다치환기 충돌 회피)이 필수.** 08-27 오전 착수 |
| 아니오 | 예 | 모순 — n 이 작아 검정력이 부족한 경우 | 실현을 늘려 다시 판정 |

### 부수 관찰 (관문 아님)

`s_r` 을 `s_ca` 와 비교합니다. 무작위 배치의 산포가 훨씬 크면, 평균이
같더라도 **다원 계열의 불확실도가 이원보다 크다**는 뜻이므로 그때 별도로
판단합니다. 미리 문턱을 걸지 않습니다.

## 4. 이 대조군이 증명하지 못하는 것 — 미리 적습니다

이 시험은 **치환기 1종**에서 배치 규약의 효과를 잽니다. v4·삼원은 2종
이상이라, "1종에서 효과 없음" 이 "2종에서도 없음" 을 **논리적으로 보장하지
않습니다.** 강한 정황이지 증명이 아닙니다.

완전히 막으려면 빌더 확장(다치환기 충돌 회피)뿐입니다. 이 문서는 그것을
대체하지 않고, **먼저 재서 필요 여부와 크기를 아는 것**입니다.

non-null 이면 확장이 필수이고, 그때 이 측정이 **고친 결과가 맞는지 검증할
기준**이 됩니다 — 확장을 먼저 하면 고친 뒤 맞게 고쳐졌는지 확인할 방법이
없습니다.

## 5. 빌더 확장 시 합격 기준 (non-null 인 경우)

    ① 기존 이원 구조를 재빌드해 **바이트 동일**해야 한다
       (mtv_cif_builder.py 는 전 계열 공유 파일이므로 회귀가 없음을 증명)

    ③ 요청 조성이 시드 재시도 없이 정확히 나온다
    ④ 이 대조군의 오프셋이 확장 후 재측정에서 사라진다
