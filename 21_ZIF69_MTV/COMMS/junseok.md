자동 푸시 감시기도 VM 과 함께 죽습니다.

#### 조치와 검증 절차 (다른 기기에 그대로 옮기실 수 있습니다)

```ini
# C:\Users\<사용자>\.wslconfig
[wsl2]
vmIdleTimeout=-1
```

적용에는 `wsl --shutdown` 이 필요하므로 **계산이 없을 때만** 하십시오.

검증은 boot_id 로 합니다. `uptime` 이나 "붙나 안 붙나" 로는 알 수 없습니다 —
어떤 `wsl` 명령이든 꺼진 VM 을 다시 띄우기 때문에 **확인 행위 자체가 증거를
지웁니다.** boot_id 는 VM 이 새로 뜨면 바뀌므로 그 함정을 피합니다.

```powershell
$b1 = wsl bash -c 'cat /proc/sys/kernel/random/boot_id'
Start-Sleep -Seconds 130          # 기본 타임아웃 60초의 2배
$b2 = wsl bash -c 'cat /proc/sys/kernel/random/boot_id'
# $b1 -eq $b2 이면 VM 이 안 내려간 것
```

이 기기 실측:

```
시험 전   e0532b3d-cc13-46f9-a788-1cebb78120dd
130초 후  e0532b3d-cc13-46f9-a788-1cebb78120dd    동일 -> 통과
```

**한계**: 이것은 **살아 있게** 할 뿐 **스스로 일을 시작하게** 하지는 않습니다.
새 배정을 자동으로 받아 띄우려면 Windows 작업 스케줄러가 따로 필요하고,
그건 사람 확인 없이 계산을 시작하는 물건이라 설계 승인이 먼저입니다.
