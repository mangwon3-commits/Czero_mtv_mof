# saIm050 자리 배치 앙상블 — 사전 등록 규약 (2026-08-26)

**이 문서는 계산을 시작하기 전에 작성됐습니다.** 수치가 하나도 없는 상태에서
무엇을 재고 어떤 답이 나오면 무엇이라고 말할지를 고정합니다. 결과를 보고
이 문서를 고치지 않습니다 (CLAUDE.md §2).

승인: 사용자, 2026-08-26. Junseok 유휴 자원 배정.

## 1. 왜 이것을 재는가

08-25 에 saIm0583 의 6실현 앙상블이 끝나면서 두 가지가 드러났습니다.

**하나.** 헤드라인이 실현 하나의 값이었습니다. 6실현 평균은
**0.7306 ± 0.0580 mol/kg** (무치환 대비 +55.7%) 이고, 배치 SD 0.0580 은
통계 오차(±0.011~0.025)의 두 배가 넘습니다.

**둘.** 그 배치 SD 를 치환 조성 전체에 얹으면 **인접 쌍이 하나도 구별되지
않습니다** (0.31~0.82 단위, 전부 1.5 미만). 그리고 —

    saIm050   0.7680   <- 실현 1개
    saIm0583  0.7306   <- 6실현 평균

**점추정에서 saIm050 이 위입니다.** 다만 saIm050 도 실현 하나뿐이라 그 값
역시 위쪽 draw 일 수 있어 뒤집혔다고 말할 수 없습니다. 지금 상태로는
**어느 쪽도 주장할 수 없습니다.**

`saIm050` 은 이 문제가 걸린 **유일한 조성**입니다. 다른 조성들은 점추정이
saIm0583 아래에 있고 배치 오차를 얹어도 위로 올라오지 않습니다.

그래서 saIm050 의 앙상블만 채우면 조성 축의 답이 닫힙니다.

## 3. 판정 기준 — 계산 전에 고정

`saIm050` 6실현(시드 0 = 기존 생산 구조 포함) 평균을 `M050`,
`saIm0583` 6실현 평균 `M0583 = 0.7306`, 배치 SD 를 `s` 로 씁니다.

두 조성의 배치 SD 가 다를 수 있으므로 결합은 `s_comb = sqrt(s050² + s0583²)`
를 씁니다. `s0583 = 0.0580` 입니다.

    |M050 - M0583| / s_comb  >= 1.5   ->  **순위 확정**
                                          큰 쪽이 승자. saIm050 이 크면
                                          승자 교체, saIm0583 이 크면 유지
    그 외 (< 1.5)                     ->  **조성 축 종료**
                                          "치환 조성끼리는 배치 오차 안에서
                                          구별되지 않는다" 를 확정으로 적고
                                          조성 최적화를 더 하지 않는다

**어느 쪽이 나오든 결론입니다.** 1.5 는 이 저장소가 이미 쓰는 문턱이고
(CLAUDE.md §2) 새로 만든 수가 아닙니다.

### 부수 판정 — 배치 SD 의 조성 의존성

`s050` 을 `s0583 = 0.0580` 과 비교합니다. 이것은 **관찰이지 관문이
아닙니다** — 미리 문턱을 걸지 않습니다. 다만 두 값이 크게 다르면
"배치 SD 를 전 조성에 동일하게 얹는다" 는 08-25 의 가정이 흔들리므로
그때 별도로 판단합니다.

## 4. 미리 적어 두는 함정

- **n 을 명시합니다.** 08-25 에 s_wc 문턱 0.0633 이 어느 n 을 상정했는지
  적혀 있지 않아 n=5 와 n=6 중 무엇을 넣을지가 모호했습니다. 이 규약의
  평균과 SD 는 **전부 n=6**(시드 0 포함)입니다.
- **leave-one-out 을 쓰지 않습니다.** 08-25 에 데스크탑과 랩탑이 각자
  독립적으로 대상을 분모에서 빼고 z 를 계산해 +2.08 / +3.75 라고 적었다가
  정정했습니다. 6개 전체로 평균·SD 를 냅니다.
- **RASPA 의 `±` 는 95% CI 입니다**(ERROR_BARS.md). 1σ 는 ÷2.776.
  배치 SD 와 통계 오차를 섞어 적지 않습니다.
- **결과 파일에 기기 태그가 필요합니다.** `water_results_<기기>.json`
  형식이 아니면 `merge_water_batches.py` 가 거부합니다.
- 앙상블 결과는 조성 격자와 **다른 폴더**에 씁니다. 같은 표에 넣으면
  merge 도구가 e1~e5 를 조성 5종으로 읽습니다.
